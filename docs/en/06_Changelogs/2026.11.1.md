### Improvements

- **Block search keywords.** With version 4.2.0 of the Search SDK, you can stop searches that contain specific words or phrases from returning results. A blocked search returns no results, and the query is not sent to the search service. Autocomplete and spelling suggestion requests are checked the same way. Matching is on whole words and ignores case and punctuation, so blocking `casino` blocks "Online CASINO!" but not "casinos".

  You set the blocked keywords in YAML, or you supply them from your own source, for example a list that CMS users manage. See [Blocking search keywords](https://github.com/silverstripeltd/silverstripe-discoverer/blob/main/docs/detailed-querying.md#blocking-search-keywords) in the silverstripe-discoverer documentation.

  The silverstripe-discoverer-search-ui module includes an example implementation. It adds a **Blocked search keywords** section to the CMS for users with the "Manage blocked search keywords" permission. See [Blocked search keywords](https://github.com/silverstripeltd/silverstripe-discoverer-search-ui#blocked-search-keywords) in the silverstripe-discoverer-search-ui documentation.

  - **New sites:** install the SDK with `composer require silverstripe/silverstripe-search-sdk:^4.2`, which includes the example implementation. Run a dev/build to add the keyword table.
  - **Existing sites:** update the SDK with `composer require silverstripe/silverstripe-search-sdk:^4.2`, then implement blocking for your site. Add your keywords in YAML, or use the example implementation as a guide to manage them in the CMS.

- **Choose which requests count as a search analytics click.** With SDK 4.2.0, you can record a click only when a person follows a search result link in a browser on your site. You can leave out crawlers, link previews, requests from other sites and error pages. Every check is off by default, so your [analytics](/features/analytics) do not change when you upgrade. See [Which requests are recorded](https://github.com/silverstripeltd/silverstripe-discoverer/blob/main/docs/detailed-result-handling.md#which-requests-are-recorded) in the silverstripe-discoverer documentation for the recommended configuration.

### Bug fixes

- **Reindexing selected classes works.** With SDK 4.2.0, the `--onlyClass` option of the `sake tasks:SearchReindex` task reindexes the class you name. Before this fix, the option stopped the task with an error. You can repeat the option to reindex several classes. Each class is reindexed only into the indexes that include it. The task now stops with an error message when an index or class you name is not configured, instead of queuing jobs that index nothing.
