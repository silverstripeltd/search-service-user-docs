### Improvements

- **Exact document counts for large indexes.** The documents list endpoint now reports the true number of documents in an index in `meta.page.total_results`, rather than stopping at 10,000. Previously any index holding 10,000 or more documents reported exactly `10,000`, which made a large index look capped or out of sync when you were checking that everything you expected had been indexed. The document count shown in the Dashboard now matches.
- **Read-only engines show a view action in the Dashboard.** The engines table rendered an edit action on every row, including engines your role gives you read access to only. Each row now resolves your permission on that engine and shows a view action where you cannot write to it. This matches how the curations list already behaves.

### Bug fixes

- **Clearing an index of more than 10,000 documents now completes.** The clear-index job sizes its work from the document total reported by the service. While that total stopped at 10,000, the job planned too few passes for a larger index: it ran out of passes with documents still indexed, the total never reached zero, and the job stopped with an error along the lines of *"Finished all steps, but the document total from your index is still showing as …"*, leaving the index partly cleared. With an exact total the job now plans the right number of passes and clears the index. No change to your site is needed. Re-run the job.

### Behaviour changes

- **`meta.page.total_pages` now reflects what you can actually retrieve.** A single query can return at most 10,000 results (see the [Limits and requirements page](/limits-and-requirements)), so `total_pages` is capped at the last page you can request. For a 25,000-document index listed 10 per page it now reports 1,000 pages rather than 2,500; `total_results` still shows the true count of 25,000. If you page through the documents list, keep using `total_pages` to decide when to stop.
- **Requesting a page beyond that limit now returns a `422`.** Asking the documents list for a page where `page.current` × `page.size` exceeds 10,000 fails validation with a message naming the limit, instead of the less specific `400` returned previously. Treat both as "past the last retrievable page".

### Maintenance

- Security and stability fixes. No customer action required.
